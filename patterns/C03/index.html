03

Pointcut

Where the mechanism applies. All four dimensions belong to the proposed match, not just its vocabulary.

Context
Producers and consumers are decoupled through topics.
Trigger
A message is published to a topic.
Structure
Topic schema, broker or bus, subscribers, and delivery policy.
Effect
Matching subscribers receive the message under declared ordering and durability rules.
04

Protected contract

The obligation that clients, operators, and auditors should be able to rely on.

Requires
Topic identity and event compatibility are defined.
Ensures
Delivery or drop is observable and subscriber selection is attributable.
Invariant
A subscriber cannot read a topic outside its authorization.
Violation
Duplicate, late, or lost delivery follows an explicit semantic contract.

Negative control

Directly invoking known listeners is C02 rather than C03.

06

Prompt + code design

An illustrative prompt and a small design sketch for the proposed contract. Names and APIs are invented; this is not a repository excerpt.

PROMPT SKETCH
Deliver events by declared topic. Record whether a subscriber received or dropped an event, and make subscriber selection attributable to the topic and compatibility rules.
CODE DESIGN / PYTHON
def publish(event, bus):
    subscribers = bus.subscribers(event.topic)
    delivered = []
    for subscriber in subscribers:
        if not subscriber.accepts(event.schema):
            delivered.append(Dropped(subscriber.id, "schema mismatch"))
            continue
        subscriber.deliver(event)
        delivered.append(Delivered(subscriber.id))
    bus.record(event.id, event.topic, delivered)

Illustrative design sketch. Publish-subscribe needs a delivery record; broadcast is not the same as delivery. This example is a teaching aid, not implementation evidence or a conformance claim.
